파라미터 연속성 검토

커넥터 기반 MEP 객체 사이에서 연속적으로 같아야 하는 속성값을 검토하는 기능입니다. 단순한 값 비교에 그치지 않고, 미연결 상태나 모델링 오류 가능성까지 함께 확인할 수 있도록 설계되어 있습니다.

주요 대상

DUCT, PIPE, CABLE TRAY, CONDUIT 등 커넥터 기반으로 연결되어야 하는 MEP 객체.

주요 목적

연속적으로 같아야 할 유틸리티, 재질, 관리용 속성값이 중간에서 끊기지 않았는지 검토.

주요 결과물

이슈 중심 결과 화면과 엑셀 산출물. 필요 시 미연결 또는 Proximity 기반 후보까지 확인 가능.

매뉴얼 목록으로 돌아가기

왜 필요한지

BIM DATA 검토 시 MEP 파일은 연결 요소로 이루어진 객체가 많습니다. Spec Break가 있는 구간이 아니라면, 연결된 요소끼리는 유틸리티, 재질 등 특정 파라미터 값이 동일하게 이어져야 하는 경우가 많습니다.

이 기능은 그런 연속성을 수작업 대신 자동으로 검토하기 위해 만들어졌습니다. 특히 납품 파일 작성 단계에서 속성 오류와 연결 오류를 함께 보려는 목적에 적합합니다.

주로 언제 쓰는지

보통 납품 파일 작성 단계에서 검토용으로 사용합니다. 납품 직전 BQC 검토 항목 중 하나로 보기 좋습니다.

대상 범위

현재 활성 문서를 바로 검토할 수 있고, 센트럴 파일이나 일반 RVT를 여러 개 등록해 일괄 검토 후 엑셀로 저장할 수도 있습니다.

대상 객체

커넥터로 연결되어 있거나 연결되어야 하는 객체를 대상으로 하며, 대표적으로 DUCT, PIPE, CABLE TRAY, CONDUIT 계열을 봅니다.

사용 전에 필요한 것과 입력값

사전 조건

  • 활성 문서 또는 검토할 RVT 목록이 준비되어 있어야 합니다.
  • 검토 파라미터는 Revit에 연결된 공유파라미터 TXT 파일 기반으로 검색해 선택합니다.
  • 공유파라미터 파일이 없으면 선택 가능한 파라미터 목록이 제한될 수 있습니다.

사용자가 선택하는 항목

  • 허용오차
  • 허용오차 단위(mm, inch)
  • 검토할 파라미터 1개 이상
  • 필요 시 추가 확인 파라미터
허용오차란?

원래는 연결되어 있어야 하지만 여러 이유로 실제 연결이 끊어진 경우에도, 커넥터 위치가 일정 범위 안에 있으면 비교 대상 후보로 잡아 검토할 수 있도록 하는 거리 범위입니다. 연결 실수, 패밀리 덮어쓰기 후 Disconnect 오류, 모델링 누락 같은 상황을 함께 잡아내는 데 유용합니다.

내부 판정 방식

1

커넥터 기반 요소 수집

문서에서 커넥터를 가진 대상 요소를 수집하고, 각 요소의 커넥터 목록을 기준으로 비교 준비를 합니다.

2

실제 연결 우선 확인

먼저 실제로 연결된 객체가 있는지 확인합니다. 실제 연결이 있으면 그 객체를 우선 비교 대상으로 사용합니다.

3

근접 후보(Proximity) 탐색

실제 연결이 없더라도 허용오차 범위 안에서 가장 가까운 커넥터 객체를 후보로 잡아 비교 대상으로 인식합니다.

4

파라미터 존재 여부와 값 비교

선택한 각 파라미터에 대해 양쪽 객체 모두 파라미터가 있는지, 값이 같은지, 비어 있는지 순서대로 판정합니다.

5

이슈 행 생성

불일치, 공유파라미터 등록 필요, 연결 대상 객체 없음, 연결 필요(근접 연결), 오류 같은 이슈를 결과 행으로 정리합니다.

결과 화면에서 봐야 할 것

값 불일치(Mismatch)

선택한 파라미터 값이 양쪽 객체에서 다를 때 표시됩니다. 가장 중요한 오류 판단 항목입니다.

연결 필요 (Proximity)

실제 연결은 없지만 허용오차 범위 안에서 가까운 대상이 잡힌 경우입니다. 속성 불일치뿐 아니라 미연결 모델링 오류 가능성도 함께 봐야 합니다.

공유파라미터 등록 필요

비교하려는 파라미터가 한쪽 또는 양쪽 객체에 존재하지 않을 때 표시됩니다. 파라미터 미등록이나 바인딩 누락을 의심합니다.

연결 대상 객체 없음

실제 연결도 없고 허용오차 범위 안에서도 비교 대상을 찾지 못한 경우입니다. 고립 객체나 연결 누락 여부를 다시 확인합니다.

정상(OK)

비교 대상 간 값이 정상적으로 일치하는 상태입니다. 일반적으로는 이슈 위주로 화면에 표시됩니다.

처리 오류(ERROR)

특정 객체 처리 중 예외가 발생한 경우입니다. 객체 상태나 패밀리, 문서 상태를 추가로 확인해야 합니다.

같이 보면 좋은 열

  • 객체 ID(Id1 / Id2): 어떤 객체 쌍인지 확인
  • 카테고리(Category1 / Category2): 어떤 계열 객체인지 확인
  • 패밀리/타입(Family1 / Family2): 패밀리와 타입 차이 확인
  • 거리(Distance): 실제 연결이 아닌 경우 객체 간 거리 확인

핵심 확인 포인트

  • 연결 판정(ConnectionType): 실제 연결인지, 근접 판정인지
  • 검토 파라미터(ParamName): 어떤 파라미터를 검토한 결과인지
  • 비교 값(Value1 / Value2): 실제 값 차이
  • 판정 상태(Status): 최종 판정

스크린샷 넣을 자리

캡처 1. 기능 진입 화면

초기 설정 화면에서는 허용오차, 단위, 검토 파라미터를 먼저 확인합니다.

커넥터 진단 결과 주요 확인 항목

캡처 2. 결과 화면

결과 테이블에서는 불일치, 근접 연결, 공유파라미터 등록 필요 상태를 확인합니다.

커넥터 진단 엑셀 주요 확인 항목

캡처 3. 엑셀 결과 예시

저장된 엑셀에서는 주요 열과 결과 상태를 함께 확인합니다.

나중에 캡처를 넣을 때 추천 순서

설정 화면 → 결과 테이블 → 엑셀 결과 순서로 넣으면 사용자가 흐름을 따라가기 가장 쉽습니다.

실무 활용과 주의사항

실무에서 어떻게 활용하면 좋은지

연속성이 필요한 파라미터를 납품 전에 점검하는 데 사용할 수 있습니다. 허용범위 내에서 가장 가까운 대상을 연결 대상 후보로 보기 때문에, 속성 오류뿐 아니라 미연결 상태와 모델링 오류 가능성도 함께 검토할 수 있습니다.

다른 기능과 같이 쓰면 좋은 조합

층검토 기능과 함께 사용하면, 레벨 영역별 속성 입력 상태와 연결 객체의 속성 연속성을 같이 볼 수 있습니다.

주의사항

허용오차를 너무 크게 잡으면 의도하지 않은 근접 객체까지 비교 대상에 들어올 수 있고, 너무 작게 잡으면 실제로는 연결되어야 하는 누락 객체를 놓칠 수 있습니다. 또한 Spec Break가 허용되는 구간까지 무조건 오류로 보면 안 되므로, 프로젝트 기준과 함께 해석해야 합니다.
