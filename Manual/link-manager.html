Link Manager

열린 프로젝트의 기존 링크를 수정하거나, 여러 RVT에 새 링크를 일괄 배치합니다. 파일별 배치·경로·참조·웍셋·고정 설정과 Excel 작업을 한 창에서 관리합니다.

열린 문서를 수정할지, 여러 파일에 추가할지 먼저 선택합니다

KKY Tool 리본에서 NWC Exporter plus 옆의 Link Manager를 누릅니다. Hub 안의 기능 목록이 아니라 전용 창에서 실행합니다. 창을 열어 둔 상태로 Revit 문서를 선택할 수 있지만, 실제 링크·저장 API가 실행되는 동안 Revit이 대기할 수 있습니다.

활성 문서: 현재 프로젝트에 추가하거나 기존 링크를 수정

  1. 문서 선택

    활성 문서를 선택하고 열린 RVT 문서에서 작업할 호스트를 고릅니다. 연결된 링크 문서나 패밀리 편집 문서는 대상이 아닙니다.

  2. 현재 목록 확인

    현재 LINK 목록에서 기존 링크와 Loaded/Not Loaded, Path Type, Workset, 고정·배치 상태를 확인합니다. 새 링크 없이 기존 행의 설정만 바꿀 수도 있습니다.

  3. 신규 링크 등록

    새로 추가할 파일이 있으면 현재 LINK 목록의 로컬 RVT 추가 또는 ACC 모델 추가를 누릅니다. 선택한 파일이 원래 화면의 작업 목록에 추가됩니다.

  4. 행별 설정

    각 작업 행의 설정을 수정합니다. 기존 링크에서 바꾸지 않을 설정은 현재 값 유지로 둡니다. 일괄 기본값을 바꾼 것과 기존 행에 적용한 것을 구분하세요.

  5. 검증 후 실행

    오른쪽의 입력 검증으로 결과를 확인한 뒤 변경 실행을 누릅니다. 기존 행은 처음에는 실행 대상에서 제외되며 설정을 변경하면 적용 대상이 됩니다. 신규 행의 사용 여부도 확인합니다.

  6. 결과와 문서 저장

    오류 행의 설명을 확인하고 필요한 결과 Excel을 저장합니다. 활성 문서는 자동 저장하지 않으므로 Revit에서 저장·동기화 여부를 직접 결정합니다.

여러 RVT: 등록한 호스트 파일에 새 링크를 일괄 추가

  1. 호스트 등록

    여러 RVT를 선택한 뒤 대상 RVT 쪽의 로컬 RVT 추가 또는 ACC 모델 추가로 링크를 배치할 파일을 등록합니다. 대상 RVT와 링크 RVT는 서로 다른 목록입니다.

  2. 링크 등록

    링크 RVT 쪽의 로컬 RVT 추가 또는 ACC 모델 추가로 추가할 파일을 등록합니다. 등록한 대상과 링크의 작업 조합을 아래 링크 작업 목록에서 확인합니다.

  3. 조합별 조정

    필요 없는 행은 실행에서 제외하고, 대상별로 다른 배치나 웍셋은 해당 행에서 수정합니다. Excel로 가져온 일부 조합을 전체 조합으로 임의 확장하지 않습니다.

  4. 검증·실행·저장

    입력 검증 결과를 확인하고 일괄 링크를 누릅니다. 여러 RVT 모드는 파일 열기와 작업 후 저장 또는 센트럴 동기화가 포함됩니다. 실행 전 원본의 별도 백업과 작업공유 권한을 확인하세요.

파일을 추가한 뒤 작업 행을 확인합니다

독립 Link Manager 창에서는 로컬 RVT 추가가 파일 선택창을, ACC 모델 추가가 모델 선택창을 엽니다. 선택한 파일은 Link Manager 안의 목록에 추가되며, 같은 창에서 설정을 이어서 확인합니다.

  • 로컬 RVT는 실제 전체 경로로 등록합니다. 같은 이름이라도 경로가 다르면 목록에서 구분해서 확인하세요.
  • ACC는 모델 선택창에서 등록합니다. 화면의 표시 이름만 복사해 클라우드 모델 주소로 사용하지 않습니다.
  • 새로 등록한 작업은 실행 대상에 포함됩니다. 전체 파일명은 한 줄로 표시되며, 긴 이름은 목록의 가로 스크롤로 끝까지 확인할 수 있습니다.
  • compact 표시를 사용해 행 높이를 줄일 수 있습니다. 검색으로 숨긴 행과 실행에서 제외한 행은 다른 상태입니다. 사용 여부와 전체 작업 수를 확인하세요.
  • 상위 Revit 버전으로 저장된 로컬 파일이나 판독할 수 없는 RVT는 실행 전에 오류로 안내합니다. 읽기 실패를 ACC 파일로 추정하지 않습니다.

배치와 링크 속성을 정합니다

Revit 영문판의 용어를 그대로 사용합니다. 상단 Positioning·Path Type·Reference Type·Pin을 바꾸면 등록한 신규 링크 행 전체에 해당 설정이 반영됩니다. 기존 링크는 적용 항목을 선택하고 위 설정 적용을 눌러 명시적으로 변경합니다. 대상별로 다른 값은 작업 행에서 확인·수정하세요.

설정적용 내용선택 예시
Auto - Origin to Origin링크와 호스트의 Internal Origin 및 축을 맞춥니다. 화면에서 보이는 모델 중심을 맞추는 옵션은 아닙니다.동일 내부 원점 기준으로 작성한 건축·구조 모델을 배치합니다.
Auto - By Shared Coordinates미리 설정된 Shared Coordinates 관계를 사용합니다. 관계가 없으면 오류로 처리하며 좌표를 자동 취득·게시하지 않습니다.좌표 관계를 사전에 맞춘 토목·건축 모델을 연결합니다.
Auto - Center to Center활성 문서는 현재 모델 뷰의 형상 중심을 사용하며 기존 링크도 포함됩니다. 여러 RVT는 시작 모델 뷰, 3D 뷰, 전체 모델 순서로 기준을 정합니다.초기 배치를 중앙 부근에 놓는 용도입니다. 좌표 정합이 필요한 납품 배치와 구분하세요.
Auto - Project Base Point to Project Base Point두 문서의 Project Base Point를 한 번 맞춥니다. 이후 기준점이 이동해도 자동으로 따라가지 않습니다.프로젝트 기준점이 같은 설계 기준을 나타낼 때 선택합니다.
현재 위치 유지기존 링크의 위치와 회전을 바꾸지 않습니다. 경로·참조·웍셋·고정만 수정할 때 사용합니다.배치는 그대로 두고 Instance Workset만 바꿉니다.
Path Type: Absolute일반 로컬 링크에 전체 경로를 사용합니다. 동일 링크 타입의 인스턴스들에 공통 적용됩니다.D:\Project\Structure.rvt처럼 고정된 위치를 사용합니다.
Path Type: Relative저장된 호스트 위치를 기준으로 상대 경로를 사용합니다. 저장되지 않은 호스트에는 적용할 수 없습니다.호스트와 링크가 함께 이동하는 프로젝트 폴더를 구성합니다.
Reference Type: Overlay이 호스트를 다른 모델에 링크할 때 해당 링크를 다시 따라 연결하지 않는 방식입니다.하위 링크를 다음 조정 모델까지 전달하지 않을 때 선택합니다.
Reference Type: Attachment이 호스트를 다른 모델에 링크할 때 해당 링크도 따라 포함되는 방식입니다.상위 모델에서 함께 보여야 하는 하위 링크에 사용합니다.
Pin: Pinned / Unpinned링크 인스턴스의 고정을 켜거나 끕니다. 현재 설정 유지는 기존 고정 상태를 바꾸지 않습니다.배치가 확정된 신규 링크를 Pinned로 지정합니다.
Cloud와 Revit Server 경로실제 모델의 경로 유형을 표시하며, 일반 로컬 파일처럼 Absolute/Relative로 바꾸지 않습니다. 표시 이름이 아니라 등록한 모델 식별 정보를 사용합니다.

Workset은 타입과 인스턴스를 구분합니다

설정의미와 입력예시
Type Workset링크 타입의 웍셋입니다. 같은 타입의 모든 인스턴스에 공통이므로 서로 다른 값을 요청할 수 없습니다.같은 구조 링크의 두 인스턴스는 모두 LINK_Structure를 사용합니다.
Instance Workset해당 링크 인스턴스의 웍셋입니다. 동일 타입의 인스턴스마다 다르게 정할 수 있습니다.반복 배치한 링크를 LINK_A, LINK_B로 나눕니다.
타입과 인스턴스를 같은 웍셋으로 지정선택한 타입 웍셋을 인스턴스에도 사용합니다. 두 값을 다르게 지정할 때는 이 선택을 해제합니다.일반적인 단일 배치는 두 값 모두 LINK_MEP로 지정합니다.
모든 링크에 공통 지정등록한 새 링크 작업에 같은 기본값을 사용합니다. 기존 작업을 바꿀 때는 일괄 적용 범위를 확인합니다.이번에 등록한 모든 링크를 LINK_Coordination에 둡니다.
링크 파일별 지정같은 링크 파일을 사용하는 여러 대상 행에 지정한 값만 적용합니다. 대상별로 다르게 설정하려면 아래 작업 행을 직접 수정합니다.건축은 LINK_Architecture, 구조는 LINK_Structure를 사용합니다.
빈 Workset / 현재 값 유지신규 작업의 빈 값은 문서 기본값을 사용합니다. 기존 링크의 변경하지 않은 항목은 현재 값을 보존합니다.기존 웍셋을 바꾸지 않고 고정만 변경합니다.
없는 Workset 생성여러 RVT 모드에서 명시적으로 선택한 경우 필요한 사용자 웍셋을 생성합니다. 활성 문서는 실제 기존 웍셋에서 선택하며 새 웍셋을 자동 생성하지 않습니다.여러 작업공유 호스트에 필요한 LINK_MEP를 준비합니다.

기존 링크는 새로 만들지 않고 설정을 변경합니다

활성 문서의 기존 행은 해당 인스턴스를 식별해 UPDATE로 처리합니다. ElementId/UniqueId를 유지하며, 변경하지 않은 값은 보존합니다.

  • 타입 단위: Path Type, Reference Type, Type Workset은 같은 타입 전체에 공통입니다. 같은 타입을 사용하는 행끼리 충돌하는 설정은 검증에서 차단합니다.
  • 인스턴스 단위: 배치, 고정, Instance Workset은 해당 인스턴스에 적용합니다. 로드된 최상위 링크의 안전한 재배치만 지원합니다.
  • 현재 배치 상태: Revit API가 최초 삽입 방법을 제공하지 않으므로 현재 좌표 관계를 바탕으로 추정한 표시입니다. 여러 기준이 일치하거나 구분할 수 없는 상태를 최초 배치 이력으로 확정하지 않습니다.
  • 변경할 문서 확인: 선택 문서가 닫히거나 다시 열리면 이전 선택·식별자로 다른 문서를 수정하지 않습니다. 새로고침하고 현재 문서와 링크를 다시 확인하세요.
공유 위치 저장이 필요한 재배치는 실행하지 않습니다기존 링크에 저장 대기 중인 공유 위치가 있거나, 이동 후 새 공유 위치 저장이 필요해지면 해당 작업을 차단하거나 이번 행 전체를 되돌립니다. 다른 Shared Site, 기울어진·반전된 링크, 언로드된 링크 등 안전하게 재배치할 수 없는 상태도 오류로 안내합니다. Positioning을 현재 위치 유지로 두고 다른 설정만 바꾸세요. 공유 위치 저장창을 자동 승인하거나 좌표를 취득·게시하는 우회 동작은 하지 않습니다.

Excel에서 먼저 작업을 작성할 수 있습니다

상단의 기본 양식 내보내기, 현재 설정 Excel 내보내기, Excel 불러오기를 사용합니다. 작성 양식과 실행 결과 Excel은 서로 다른 파일입니다.

1. 기본 양식: 신규 링크 작업을 네 열로 작성

파일을 등록하지 않아도 링크_매니저_기본양식.xlsx를 내보낼 수 있습니다. 링크 매니저 시트의 빈 행에 작성합니다. 기본 양식은 25개의 빈 행을 제공하며 최대 50,000행까지 읽습니다. 작성 안내 시트의 예시는 실행 행이 아닙니다.

대상 RVT 경로링크 RVT 경로배치 방식웍셋
D:\Project\Host_A.rvtD:\Project\Structure.rvtAuto - Origin to OriginLINK_Structure
D:\Project\Host_B.rvtD:\Project\Structure.rvtAuto - Origin to OriginLINK_Structure
  • 활성 문서: 대상 RVT 경로를 비우고 링크 RVT 경로를 입력합니다. 화면에서 선택한 호스트에 신규 링크를 추가합니다.
  • 여러 RVT: 각 행에 대상과 링크의 전체 경로를 모두 입력합니다. 위 예시는 같은 구조 파일을 서로 다른 두 호스트에 추가합니다.
  • 배치 방식: 드롭다운에서 영문 Revit 옵션을 선택합니다. 비우면 Auto - Origin to Origin입니다.
  • 웍셋: 입력한 기존 웍셋을 타입과 인스턴스에 함께 적용합니다. 비우면 문서 기본값을 사용하며, 기본 양식에서는 새 웍셋을 만들지 않습니다.
  • 기본 양식은 Overlay를 사용합니다. Absolute/Relative, 고정, Attachment, 타입·인스턴스별 웍셋, 없는 웍셋 생성이나 기존 링크 UPDATE가 필요하면 현재 설정 양식을 사용하세요.
  • 경로와 설정은 수식이 아니라 값으로 입력합니다. 입력 행을 저장한 뒤 Excel 불러오기로 가져와 화면의 작업 목록과 오류를 확인합니다.

2. 현재 설정 양식: 행별 상세 설정과 기존 링크 변경

등록한 작업이 있으면 링크_매니저_등록내용.xlsx를 내보냅니다. 현재 schema 4는 경로 유형·고정과 기존 링크 식별 정보를 함께 보관하며, schema 1/2/3과 구형 한글 선택값도 계속 읽습니다.

시트 / 항목수정하는 내용
링크 매니저실행할 작업 행입니다. 사용 여부, 대상·링크 경로, 배치 방식, 하위 링크 포함 방식, 타입·인스턴스 웍셋, 없는 웍셋 생성, 경로 유형과 고정을 수정합니다.
작업 설정 / 등록 파일화면을 다시 구성하고 새 행의 기본값을 보관합니다. 기존 작업 행의 실행값을 자동으로 덮어쓰거나 전체 조합으로 다시 만들지는 않습니다.
기존 링크의 숨김 식별 열UPDATE 대상과 문서를 확인하는 정보입니다. 삭제·수정하거나 새 링크 행에 복사하지 않습니다. 기존 링크는 화면에서 내보낸 양식을 사용하세요.

Excel을 가져온 뒤에도 동일한 링크 작업 목록에서 설정을 확인·수정합니다. 화면은 한 번에 100행까지 표시하지만 Excel 저장·검증·실행은 전체 작업에 적용합니다. ACC는 화면에서 모델을 등록하고 현재 설정 양식으로 왕복하세요.

행별 결과를 확인하고 Excel을 저장합니다

사전 검증 결과와 실행 종료 결과를 구분합니다. 사전 검증 통과는 링크 추가·문서 저장 완료를 뜻하지 않습니다. 완료 화면에서 각 행의 처리 상태와 설명을 확인하세요.

  • 버전 불일치, 파일 없음, 입력 오류, 웍셋 또는 같은 타입 설정 충돌은 해당 원인을 확인하고 수정합니다.
  • 공유 위치 보호로 되돌린 행은 링크 변경 완료로 계산하지 않습니다. 다른 설정까지 해당 행 전체가 되돌려졌는지 결과 설명을 확인합니다.
  • 중지하거나 실행에서 제외한 행은 정상 적용과 구분합니다. 전체 행 수만 보고 모든 링크가 적용됐다고 판단하지 않습니다.
  • 결과를 저장하려면 결과 Excel 내보내기 (.xlsx)를 누르고 저장 위치를 선택합니다. 기본 파일명은 링크_매니저_결과_20261014_083000.xlsx처럼 실행 시각을 포함합니다. 저장창에서 이름을 바꿀 수 있습니다.
결과 시트확인할 내용
결과 요약사전 검증 / 실행 종료 단계, 완료·내보낸 시각, 전체 행과 처리 상태별 수량, 전체 오류를 확인합니다.
행별 결과대상·링크 경로, 결과·설명·입력 오류와 적용 당시의 배치·참조·웍셋·경로·고정, 링크 식별 정보를 확인합니다.
이 기능의 Excel 저장 방식BQC의 한글/영문 × 통합/파일별 네 가지 결과 내보내기와 다릅니다. Link Manager는 현재 작업 전체의 결과를 한 XLSX로 저장하며, 열 제목은 한국어, Revit 선택값은 영문 용어로 표시합니다. 저장한 결과를 편집용 등록 양식으로 대신 사용하지 않습니다.
처리 방식

적용 순서와 보호 규칙

화면에서 설정한 값이 어떤 순서로 모델에 적용되는지 설명합니다.

  1. 요청 구성: 모드, 열린 문서의 세션 식별 정보, 사용할 작업 행과 실제 행별 설정을 보냅니다. 경로가 같은 등록 중복과 Excel의 행별 작업은 구분합니다.
  2. 실행 전 검사: 지원하는 입력·모델 식별 정보, 실제 파일과 저장 버전, 타입 설정 충돌, 웍셋·배치 가능 조건을 확인합니다. 상위 버전·판독 불가 로컬 RVT는 네이티브 열기·링크 호출 전에 차단하고 신규 링크 생성 직전에도 다시 검사합니다.
  3. 신규 LINK: 등록한 호스트와 링크 조합에 신규 인스턴스를 배치하고 행별 경로·참조·웍셋·고정을 적용합니다. Shared Coordinates 관계를 대신 만들거나 이전 링크를 임의로 재로드하지 않습니다.
  4. 기존 UPDATE: 실제 타입·인스턴스 식별자를 다시 확인합니다. 같은 타입의 설정과 각 인스턴스의 설정을 구분하고 변경한 항목만 적용합니다. 기존 인스턴스를 삭제·재생성하지 않습니다.
  5. 재배치 검사와 되돌림: 기존 공유 위치 저장 대기와 배치 가능 상태를 먼저 확인합니다. 이동 후 공유 위치 저장이 필요해지면 해당 행 전체를 되돌리고 원래 상태가 복구됐는지 확인합니다. 복구 검증 실패는 문서 단위의 치명 오류로 처리합니다.
  6. 작업 종료: 적용·오류·미실행 상태를 행별로 기록합니다. 활성 문서는 열린 상태로 남기고 사용자가 저장합니다. 여러 RVT는 해당 파일의 저장 또는 센트럴 동기화 결과까지 확인합니다.

사용 전 확인할 범위

  • 호스트와 링크의 버전, 접근 권한, 작업공유 상태와 원본 백업을 확인하세요. 오래 걸리는 Revit API 작업이 동시에 모델 편집을 허용하는 것은 아닙니다.
  • 2021은 빌드·API·UI·설치 파일 대조를 확인했지만 실제 Revit 실행은 확인하지 못했습니다. 앞선 기능 수정은 Revit 2019/2023/2025/2027의 시험 모델에서 확인했고, 영문 용어 변경은 이후 별도의 빌드·UI·Excel·서명 대조를 수행했습니다.
  • 현장 센트럴과 실제 ACC 전체 시나리오를 검증 완료한 것으로 보장하지 않습니다. 해당 환경에서는 작업 사본 또는 제한된 대상부터 결과·저장 상태를 확인하세요.
