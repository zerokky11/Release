Schedule 추출·입력

Revit Schedule 정의를 기준으로 활성 문서 또는 여러 RVT의 데이터를 Excel로 추출하고, 식별 열로 요소를 다시 확인한 뒤 Instance·Type 파라미터 값을 입력합니다.

빠른 시작

Export와 Import는 서로 다른 작업입니다

Export는 Schedule 정의를 골라 데이터를 만들고, Import는 Excel의 식별 열과 Revit 요소를 대조한 뒤 지정 파라미터에 값을 씁니다. 처음에는 Export로 양식을 만든 뒤 그 파일을 수정해 Import하는 흐름이 가장 안전합니다.

  1. 작업 탭 선택

    상단에서 Export 또는 Import를 선택합니다.

  2. 기준과 대상 준비

    Export는 Schedule과 RVT를, Import는 Excel과 RVT를 준비합니다.

  3. 세부 설정

    추출 형태 또는 Instance·Type 매핑을 지정합니다.

  4. 사전 확인

    선택 개수, 식별 열, 파라미터 검사 결과를 확인합니다.

  5. 실행

    활성 문서 또는 등록한 여러 RVT를 실행합니다.

  6. 결과 저장

    Export는 결과창에서 Excel 형식과 저장 위치를 선택합니다.

권장 첫 작업 활성 문서에서 해당 객체 전체로 Export해 식별 열이 포함된 Excel을 만든 뒤, 값 열만 수정해 Import 테스트를 진행합니다.

기준 Schedule과 추출 방식을 정합니다

화면의 Schedule을 그대로 읽을지, Schedule에 잡히는 실제 요소를 행 단위로 읽을지 먼저 결정합니다.

설정선택값무엇이 달라지는가예시
기준 Schedule 문서활성 문서 Schedule현재 열린 프로젝트 문서의 비템플릿 Schedule 목록을 사용합니다.현재 모델의 장비 일람표를 바로 추출
기준 Schedule 문서Schedule RVT 선택Schedule을 모아 둔 별도 RVT에서 정의를 읽습니다. 대상 RVT가 달라도 같은 기준을 반복 적용할 때 사용합니다.Schedule_Standards.rvt의 표준 일람표를 여러 납품 RVT에 적용
추출 방식Schedule 표시 그대로Revit 화면에 표시되는 본문 셀을 읽습니다. 그룹, 합계, 계산 결과와 표시 순서를 보이는 형태로 보존합니다.수량 합계와 그룹 제목까지 보고서처럼 저장

Export 2 / 3

적용할 Schedule을 선택합니다

불러온 기준 문서의 비템플릿 Schedule만 표시됩니다. 이름 검색과 전체 선택을 사용할 수 있고, 각 항목의 표시 필드 수를 함께 확인할 수 있습니다.

  1. 목록 불러오기

    활성 문서 또는 선택한 Schedule RVT를 열어 Schedule 이름과 표시 필드 수를 수집합니다.

  2. Schedule 선택

    같은 데이터 구조가 필요한 Schedule만 체크합니다. 이름 검색은 표시 목록만 좁히고 기존 선택은 유지합니다.

  3. 대상별 임시 적용

    기준 문서와 대상 문서가 다르면 선택 Schedule을 대상 문서에 임시 복사해 데이터를 읽은 뒤 트랜잭션을 되돌립니다. 대상 RVT에는 복사본이 저장되지 않습니다.

Import

Excel 열을 Revit 파라미터에 연결합니다

Import 탭은 파일 선택, 시트·값 열 선택, 파라미터 매핑, 빈 셀·동기화 옵션을 한 화면에서 설정합니다.

1. Excel 파일과 식별 열

Excel을 선택하거나 화면에 드롭합니다. 다음 헤더는 요소 확인용으로 사용되며 값 열 선택 목록에는 나타나지 않습니다.

필수 식별허용 헤더 예역할
RVTRVT File, RVT 파일, File Name파일명 기준으로 대상 문서를 찾습니다.
요소 IDElement ID 또는 Unique IDElement ID를 먼저 찾고, 없으면 Unique ID를 사용합니다.
FamilyFamily, 패밀리찾은 요소의 Family가 Excel과 같은지 재검증합니다.
TypeType, 타입찾은 요소의 Type이 Excel과 같은지 재검증합니다.

2. 시트와 값 열

입력할 시트를 체크한 뒤 Comments, Mark, Asset Code처럼 실제로 쓸 값 열만 선택합니다. 선택한 열마다 매핑 행이 하나씩 생깁니다.

3. Instance / Type 매핑

설정의미예시
InstanceExcel 행에서 찾은 개별 요소의 파라미터에 값을 씁니다.각 장비의 Mark, Comments
Type요소가 참조하는 Type 요소의 파라미터에 값을 씁니다. 같은 Type은 여러 Instance가 공유합니다.Manufacturer, Model
Revit 파라미터 이름실제로 값을 쓸 파라미터 이름입니다. 기본값은 Excel 열 이름이며 필요하면 다른 이름으로 바꿉니다.Excel Asset Code → Revit KKY_AssetCode
파라미터 확인활성 문서 또는 등록 RVT에서 사용 가능한 Instance·Type 이름과 행 일치 건수를 미리 읽습니다.자동완성 목록으로 오타 방지

4. Import 옵션

옵션꺼짐켜짐
빈 Excel 셀로 기존 값 지우기빈 셀은 건너뛰어 기존 Revit 값을 보존합니다.쓰기 가능한 파라미터의 기존 값을 지웁니다.
활성 문서 Import 후 중앙파일과 동기화현재 문서에 값만 적용합니다.Workshared 활성 문서에 변경을 적용한 뒤 중앙파일과 동기화합니다.
동기화 코멘트활성 문서 동기화와 여러 RVT 중앙파일 처리에 기록할 설명입니다. 예: KKY Tool Schedule Excel Import
작동 논리

값을 쓰기 전에 요소와 파라미터를 단계별로 검증합니다

Excel의 Element ID 하나만 믿고 값을 쓰지 않습니다. 파일, 요소, Family, Type, 파라미터 상태를 순서대로 확인하며 실패한 행은 건너뜁니다.

  1. 대상 문서 일치

    RVT File 값을 경로와 확장자를 정리한 파일명으로 비교해 대상 RVT를 찾습니다.

  2. 요소 찾기

    Element ID를 먼저 사용하고, 해당 값이 없거나 찾지 못하면 Unique ID를 사용합니다.

  3. Family / Type 재검증

    Excel에 값이 있으면 실제 요소의 Family와 Type이 같은지 비교합니다. 다르면 잘못된 요소로 판단해 해당 행을 건너뜁니다.

  4. 파라미터 상태 확인

    매핑 이름으로 Instance 또는 Type 파라미터를 찾고, 읽기 전용이면 오류로 기록합니다.

  5. 값 변환

    문자열, 정수·Yes/No, 현재 Revit 단위를 사용하는 실수, ElementId 형식을 지원합니다. 변환할 수 없는 값은 쓰지 않습니다.

  6. Type 충돌 방지

    같은 Type 파라미터에 서로 다른 Excel 값이 들어오면 어느 값을 적용할지 임의 결정하지 않고 해당 Type 반영을 건너뜁니다.

  7. 저장과 복구

    처리 중 예기치 않은 오류가 나면 현재 트랜잭션을 되돌립니다. 여러 RVT는 실제 변경이 있는 파일만 저장·동기화합니다.

이미 Revit에 열려 있는 RVT 여러 RVT Import에서는 이미 열린 파일을 다시 처리하지 않습니다. 그 파일은 Revit에서 활성 문서로 전환한 뒤 활성 문서 Import를 사용합니다.
