검사 및 유지관리

현재 모델 검사

현재 활성 프로젝트의 로더블 패밀리와 시스템 타입을 선택한 공종의 표준 스냅샷과 비교하고, 차이·누락·추적 상태를 검토합니다.

검사 전 확인

현재 프로젝트

화면에 표시된 활성 프로젝트가 검사하려는 호스트 RVT인지 확인합니다.

선택된 검사 기준

건축·전기·소방·설비 등 현재 업무에 맞는 등록 표준을 선택합니다.

표준 스냅샷

선택 공종의 표준 RVT가 등록·스캔되어 있어야 비교를 실행할 수 있습니다.

저장 상태

최근 변경 내용을 포함하려면 검사 전에 현재 프로젝트를 저장하거나 동기화하는 것이 좋습니다.

공종 기준을 반드시 확인합니다.다른 공종 표준에도 같은 이름의 패밀리가 있을 수 있습니다. 잘못된 기준을 선택하면 정상 항목도 차이로 판단될 수 있습니다.
표준 RVT가 마지막 스캔 뒤 변경되었다면 검사를 시작하지 않습니다.화면에 재스캔 필요가 표시되면 관리자가 원본 파일을 확인하고 정밀 스캔을 완료해야 합니다. 오래된 기준으로 결과를 만드는 것을 막기 위한 차단입니다.

실행 방법

  1. 왼쪽 메뉴에서 모델 검사를 엽니다.

    화면은 캐시된 기준과 최근 상태만 먼저 표시하며, 이 단계에서 원본 표준 RVT를 다시 스캔하지 않습니다.

  2. 선택된 검사 기준을 확인합니다.

    상단 공종 칩 중 사용할 기준을 선택합니다. 스캔 필요가 보이면 관리자가 해당 표준을 먼저 갱신해야 합니다.

  3. 프로젝트 검사를 실행합니다.

    현재 모델의 로더블 패밀리와 시스템 타입을 선택 기준의 캐시된 표준 스냅샷과 비교합니다.

  4. 필요한 추가 진단을 실행합니다.

    시스템 타입 문제는 시스템 타입 정밀 진단, 추적 정보는 추적 스탬프와 추적 확인을 사용합니다.

  5. 결과와 다음 작업을 확인합니다.

    일치·차이·프로젝트 전용·실패 건수를 확인하고 관리자 업데이트 또는 요청 등록 여부를 결정합니다.

검사 논리

이름이 같은지만 보는 검사가 아닙니다. 정밀 검사에서는 표준 스냅샷과 현재 프로젝트의 구조적 내용을 비교합니다.

로더블 패밀리 식별

패밀리명과 카테고리 식별을 먼저 맞춥니다. 같은 이름이지만 카테고리가 다르면 불일치로 차단합니다.

패밀리 정밀 내용

타입, 파라미터, 하위 패밀리 메타데이터, Lookup CSV·사이즈 테이블을 포함한 콘텐츠 Fingerprint를 비교합니다.

시스템 타입 정의

시스템 패밀리 종류와 타입 정의, 크기 수·범위, 레이어 구성 등 의미 있는 구조를 비교합니다. 상세 비교 옵션이 켜져 있으면 Railing의 Handrail·Top Rail·Baluster, Stair의 Run·Landing·Support도 포함합니다.

시스템 의존 관계

라우팅 프리퍼런스 그룹·규칙, 연결 부품, 클래스와 카테고리, Curtain Panel·Mullion 등 적용에 필요한 의존 항목을 비교합니다.

추적 정보

Family Browser로 반영한 항목의 출처, 표준 대상, 저장·동기화 확정 여부를 확인합니다.

검사 실패 보존

Fingerprint를 만들지 못한 패밀리는 누락시키지 않고 실패 목록과 사유를 비교 리포트에 남깁니다.

결과 읽기

결과창은 검사 대상과 기준, 비교 건수, 차이 건수, 프로젝트 전용 항목, Fingerprint 실패와 저장된 리포트를 요약합니다.

  • 표준과 일치: 선택 기준의 구조와 현재 프로젝트 항목이 일치합니다.
  • 표준과 다름: 대응 항목은 있지만 Fingerprint 또는 의미 구조가 다릅니다.
  • 프로젝트 전용: 현재 프로젝트에만 있고 승인 표준에 대응 항목이 없습니다.
  • 카테고리 불일치: 이름은 같아도 다른 카테고리에 있어 자동 반영할 수 없습니다.
  • 실패 목록: 정밀 내용을 읽지 못한 항목과 원인이 별도로 보존됩니다.
첫 정상 검사는 프로젝트 이름 기준선도 준비합니다.검사가 성공하면 현재 프로젝트의 패밀리·패밀리 타입·시스템 타입 이름 목록을 확인된 기준선으로 저장합니다. 이후 추가·삭제된 이름은 프로젝트 변경 추적에서 구분해 볼 수 있습니다.

보호 항목 삭제 검토

관리 대상으로 추적하던 패밀리 또는 타입이 삭제되면 관리자 화면에 보호 항목 삭제 검토가 표시됩니다. 삭제 항목은 항상 자동 복구되는 것이 아니므로 현재 모델 검사를 다시 실행해 표준과 비교해야 합니다.

  1. 삭제 감지 기록을 확인합니다.

    감지 시각, 사용자, 항목 구분, 이름, 카테고리, Element ID와 필요한 작업이 표시됩니다.

  2. 현재 모델 검사 실행을 누릅니다.

    등록된 표준 RVT 스냅샷을 기준으로 실제 누락 여부와 차이를 다시 계산합니다.

  3. 누락 항목을 표준 RVT에서 복구합니다.

    검사 결과가 누락 또는 표준과 다름이면 표준 패밀리·타입을 다시 로드하거나 적용한 뒤 검사를 반복합니다.

삭제 감지 표시는 복구 완료 표시가 아닙니다.현재 모델 검사 결과가 표준과 일치하는지 확인한 뒤 운영을 계속합니다.

Excel 검토 목록

현재 모델 검사는 검토가 필요한 행을 .xlsx로 저장합니다. CSV 결과 내보내기는 제공하지 않습니다. Excel 추출 버튼은 검토 필요·표준과 다름 항목 또는 자동 처리된 대화상자 기록이 1건 이상 있을 때만 표시됩니다.
