프로젝트 변경 추적

승인된 이름 목록에서 벗어난 패밀리·타입을 찾고, 필요할 때 프로젝트 요소의 생성·수정·삭제 이력까지 저장합니다. 두 기능은 목적과 정확도가 다르므로 따로 설정합니다.

두 가지 추적을 구분해서 사용합니다

구분확인하는 것기준이 확정되는 시점권장 용도
프로젝트 이름 카탈로그패밀리명, 패밀리 타입명, 시스템 타입명의 추가·삭제현재 모델 검사 성공 또는 관리자의 이름 기준선 승인표준 밖 이름의 빠른 발견
프로젝트 요소 변경 이력Element ID별 생성·수정·삭제와 사용자·문서·작업 세션일반 RVT 저장 또는 워크셰어링 RVT 중앙 동기화 성공누가 어떤 요소를 바꿨는지 운영 이력 확인
이름이 같다고 내용까지 같다는 뜻은 아닙니다.이름 기준선은 빠른 감지용입니다. 타입 파라미터와 시스템 구성까지 표준과 같은지 판단하려면 현재 모델 검사를 실행합니다.

프로젝트 이름 기준선 만들기

기준선이 없는 프로젝트는 현재 이름이 정상인지 새로 추가된 것인지 구분할 수 없습니다. 새 프로젝트를 운영에 넣을 때 한 번 승인합니다.

  1. 가장 안전한 방법은 현재 모델 검사를 먼저 실행하는 것입니다.

    선택한 표준과 상세 비교가 정상 완료되면 그 시점의 프로젝트 이름 목록을 검사 완료 기준선으로 저장합니다.

  2. 상세 검사를 당장 할 수 없다면 관리자 홈에서 이름 기준선만 승인합니다.

    현재 이름 목록을 기준선으로 승인은 현재 보이는 이름을 출발점으로 삼습니다. 내용 일치 여부까지 승인하는 기능은 아닙니다.

  3. 승인 후 홈을 새로고침합니다.

    이후 새 패밀리·타입이 생기거나 기존 이름이 없어지면 추가·삭제 건수와 목록이 표시됩니다.

이름 변경 결과 읽기

표시판정 근거다음 작업
Browser 기록과 일치Family Browser의 로드·적용 기록과 같은 이름 변경을 찾았습니다.저장·동기화가 완료되었는지 확인하고 모델 검사로 내용 일치를 확인합니다.
외부 / 미추적 변경이름 변화는 있지만 Family Browser 작업 기록과 연결되지 않습니다.Revit 기본 명령, 다른 애드인, 외부 사용자의 작업 가능성을 검토합니다.
삭제됨기준선에 있던 이름이 현재 프로젝트에서 사라졌습니다.의도한 정리인지 확인하고 보호 항목이면 모델 검사 후 복구합니다.
기준선 필요비교할 승인 시점이 없습니다.현재 모델 검사 또는 관리자 이름 기준선 승인을 실행합니다.
Browser 기록과 일치는 작업자를 확정하는 증거가 아닙니다.동일한 이름 변화와 애드인 기록을 연결해 분류한 결과입니다. 정확한 사용자·시각·Element ID가 필요하면 아래 요소 변경 추적을 켭니다.

요소 생성·수정·삭제 추적 설정

관리자 설정의 프로젝트 요소 생성·수정·삭제 추적을 켜면 Revit 문서 변경 이벤트를 로컬 작업 세션에 모았다가 저장 경계에서 확정합니다.

  1. 관리자 설정에서 변경 추적을 켭니다.

    설정은 관리 정책으로 저장됩니다. 정확한 사용자 기록이 필요하면 프로젝트를 편집하는 모든 PC에 같은 버전의 Family Browser가 설치되어 있어야 합니다.

  2. 프로젝트를 저장한 상태에서 작업을 시작합니다.

    한 번도 저장하지 않은 문서는 안정적인 프로젝트 식별자가 없으므로 최근 변경 이력을 열 수 없습니다.

  3. 작업 후 올바른 저장 경계를 완료합니다.

    일반 RVT는 저장 성공, 워크셰어링 RVT는 중앙과 동기화 성공 뒤 공유 이력으로 확정합니다.

  4. 홈의 최근 변경 이력 보기에서 확인합니다.

    현재 저장된 프로젝트 또는 중앙 모델의 식별자와 일치하는 기록만 읽습니다.

저장과 동기화가 기준이 되는 이유

문서 상태확정 동작그 전까지의 처리
일반 RVT저장 또는 다른 이름으로 저장 성공변경 이벤트를 현재 로컬 세션의 대기 기록으로 보관
워크셰어링 RVT중앙과 동기화 성공로컬 저장은 보호용 체크포인트만 만들며 공유 이력으로 확정하지 않음
저장/동기화 실패확정하지 않음실패한 작업을 완료된 변경으로 기록하지 않음
저장하지 않고 닫기확정하지 않음문서에 남지 않은 세션 변경은 최종 이력에서 제외
워크셰어링 로컬 저장과 중앙 동기화는 같은 작업이 아닙니다.다른 사용자가 볼 수 있는 공유 변경 이력은 중앙 동기화가 성공한 뒤에만 생성됩니다.

관리 경로가 끊긴 상태에서 작업했을 때

저장 시점에 공용 관리 폴더를 사용할 수 없으면 변경 기록을 버리지 않고 보호된 로컬 대기열에 보관합니다. 연결이 복구된 뒤 홈 새로고침 또는 다음 확정 작업에서 전송을 다시 시도합니다.

손상·스키마 불일치·잠금 경고가 보이면 로컬 폴더를 삭제하지 않습니다.로그와 지원 코드를 관리자에게 전달하고 복구 절차를 먼저 확인합니다.

최근 변경 이력과 Excel

  • 최근 변경 창은 현재 프로젝트와 일치하는 저장 커밋을 최신순으로 읽습니다.
  • 화면은 성능을 위해 최근 커밋과 행 수를 제한해 미리보기하며, 전체 Excel은 사용자가 내보내기를 눌렀을 때만 만듭니다.
  • 각 행에는 변경 종류, Element ID, 카테고리, 타입, 사용자, 문서, 저장·동기화 시각과 세션 정보가 포함될 수 있습니다.
  • 한 번도 저장하지 않은 프로젝트는 식별할 수 없으므로 먼저 저장하라는 안내가 나옵니다.
이력은 감사 보조 자료입니다.애드인이 설치되지 않은 PC에서 발생한 변경, Revit 외부에서 교체된 파일, 복구·업그레이드 과정의 변화는 정확한 작업자 이벤트가 없을 수 있습니다. 이름 카탈로그와 현재 모델 검사 결과를 함께 봐야 합니다.
