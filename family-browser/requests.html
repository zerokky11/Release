업무 흐름

추가 요청

승인 목록에 없는 패밀리·시스템 타입 또는 현재 프로젝트의 더 나은 항목을 표준에 반영해 달라는 요청을 애드인 안에서 등록하고 추적합니다.

요청 종류

일반 요청

특정 패밀리나 시스템 타입에 속하지 않는 운영 문의와 개선 의견을 등록합니다.

없는 패밀리

승인 표준 라이브러리에 새로 편입되어야 할 로더블 패밀리를 요청합니다.

없는 시스템 타입

새 시스템 타입, 라우팅 프리퍼런스 또는 필요한 의존 항목을 요청합니다.

표준 업데이트

현재 프로젝트 항목이 기존 표준보다 낫다고 판단될 때 표준 변경 검토를 요청합니다.

요청 등록 방법

  1. 왼쪽 메뉴에서 요청 탭을 엽니다.

    요청 목록은 요청 탭을 열 때 읽습니다. 시작할 때 요청 저장소 전체를 미리 읽지 않습니다.

  2. 요청 종류를 선택합니다.

    일반, 패밀리, 시스템, 표준 업데이트 중 목적에 맞는 카드를 선택하거나 요청 등록하기를 누릅니다.

  3. 공종을 입력합니다.

    예: Mechanical, Electrical, 건축, 설비처럼 담당 표준을 구분할 수 있는 공종을 입력합니다.

  4. 제목과 내용을 작성합니다.

    제목에는 대상 항목명을 명확히 쓰고, 내용에는 사용 목적, 필요한 타입, 현재 문제와 원하는 결과를 적습니다.

  5. 필요한 참고 파일을 첨부합니다.

    RFA, RVT, PDF, DOCX, XLSX, PPTX, TXT 등 설명에 필요한 파일만 선택합니다. 첨부는 선택 사항입니다.

  6. 등록 후 목록에서 상태를 확인합니다.

    저장 경로는 Family Browser가 처리합니다. 일반 사용자는 요청 저장소 폴더를 직접 선택하거나 열 필요가 없습니다.

저장 방식과 권한

  • 요청 본문은 요청 저장소의 개별 JSON 기록으로 저장되고, 첨부파일은 요청별 관리 폴더에 함께 보관됩니다.
  • 일반 사용자 화면에는 내부 저장 경로를 노출하지 않습니다. 연결 실패 시 관리자에게 Family Request Path Settings 확인을 요청합니다.
  • 목록 새로고침은 현재 저장소의 요청 기록을 다시 읽습니다.
  • 요청 저장소 열기, 공유 요청 폴더 지정, 첨부 폴더 열기는 관리자 모드에서만 보일 수 있습니다.
  • 읽을 수 없는 요청 JSON은 목록에서 완전히 버리지 않고 오류 기록 대상으로 남깁니다.
공용 관리 폴더를 사용합니다.팀 공유 요청 저장소는 로컬 C 드라이브, AppData 또는 개인 사용자 폴더가 아니라 팀이 읽고 쓸 수 있는 관리 경로여야 합니다.

여러 사용자가 같은 요청을 다룰 때

요청은 개정 번호와 내용 토큰을 함께 확인한 뒤 저장합니다. 내가 요청을 열어 둔 사이 다른 사용자가 상태나 첨부를 바꿨다면 오래된 화면으로 덮어쓰지 않습니다.

  • 상태 변경이나 삭제 시 현재 저장소의 최신 개정과 화면의 개정을 비교합니다.
  • 충돌이 있으면 작업을 거부하고 최신 요청 목록을 다시 읽습니다. 새 내용을 확인한 뒤 다시 실행합니다.
  • 첨부파일은 내용 기반 이름으로 보관해 같은 파일의 중복과 바뀐 내용을 구분합니다.
  • 요청 삭제는 작성자 또는 관리자만 할 수 있으며, 삭제 전 요청 본문·상태·첨부 목록을 복구 가능한 감사 스냅샷으로 보존합니다.
충돌 안내는 저장 실패가 아니라 데이터 보호 동작입니다.목록 새로고침 후 누가 무엇을 바꿨는지 확인하고 필요한 변경만 다시 적용합니다.
